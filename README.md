# An Axiomatic Framework for Reinforcement Learning in Open Multi-Agent Systems

This is the code release for the paper, [An Axiomatic Framework for Reinforcement Learning in Open Multi-Agent Systems](https://arxiv.org/abs/2611.03301). This codebase was built on top of the [NAHT](https://github.com/carolinewang01/naht) codebase.

The following additions and modifications were made by us: 
- Implementation of Shapley Machine / Banzhaf Machine, the approaches proposed in the paper, in the files `src/learners/poam_shapley_learner.py` and `src/learners/ppo_shapley_learner.py`. `src/learners/poam_shapley_learner.py` indicates SM-POAM / BM-POAM, while `src/learners/ppo_shapley_learner.py` indicates SM-IPPO / BM-IPPO
- Configs of SM-POAM / BM-POAM for MPE and SMAC, in the files `src/config/algs/mpe/poam_shapley.yaml` and `src/config/algs/sc2/poam_shapley.yaml`
- Configs of SM-IPPO / BM-IPPO for MPE and SMAC, in the files `src/config/algs/mpe/ippo_shapley.yaml` and `src/config/algs/sc2/ippo_shapley.yaml`

# Getting Started 
This section covers installation instructions, configuring repo-wide user variables, and downloading uncontrolled agent policies, which refers to the [NAHT](https://github.com/carolinewang01/naht) codebase.

## Installation
1. We recommend creating a conda environment. As of Nov. 2024, these installation instructions were verified with Python 3.10 and PyTorch 2.5. Note that `torch_scatter` is not required to reproduce the experiments in our paper, but is necessary to import the PAC method (inherited from ePyMARL).

```
conda create -n <my_env> python=3.10
conda install pytorch pytorch-cuda=12.1 -c pytorch -c nvidia
pip install torch-scatter -f https://data.pyg.org/whl/torch-2.5.0+cu121.html
```

2. Install environment and repository package requirements via 
```
pip install -r requirements.txt
pip install -r env_requirements.txt
```
The `env_requirements.txt` will install the following environments, used in our experiments: 
- [SMAC](https://github.com/oxwhirl/smac)
- Our fork of [MPE](https://github.com/carolinewang01/multiagent-particle-envs)

2. Install StarCraft2 
Please see the instructions in the [SMAC](https://github.com/oxwhirl/smac) codebase for instructions to install the StarCraft II game. 

## Configuring Results Directories

Configuring results directories: modify `src/config/user_info.yaml` with your preferred base path for results, and preferred directory where uncontrolled agent policies will be stored. 
By default, results will be written to the folder `./naht_results`, and uncontrolled agents should be stored at `./uncntrl_agents`.

# Instructions to Replicate the NAHT Experiments with Shapley Machine
**Preparation**:
To run NAHT experiments, a set of teammates to train with must be provided. 
The teammates should be policy checkpoints that were generated by this codebase. 
During training time, the information to reload the policies is automatically read out of the configs stored by Sacred.
Note that the teammate policies are assumed to be stored relative in the `base_uncntrl_agents` directory specified in `src/config/user_info.yaml`. See "Getting Started" for links to download the agents used in this paper. 

**Note**:
The `shapley_loss_coef` and `shaped_reward_coef` refer to $\alpha$ and $\beta_{2}$ in the paper, respectively. The `value_loss_coef` refers to $\beta_{1}$ in the paper, which is always fixed to $0.5$ in this paper. 

**The five seeds used in experiments are: 112358, 112359, 112360, 112361, 112362.**

## Training Models for Vanilla NAHT Tasks
This is the main task as shown in the paper. The general pipeline is that we train our models by interacting uncontrolled agents that are pretrained with the same seed (112358 is selected in this paper), and later on evaluating our models with uncontrolled agents with different seeds (i.e., 1285842, 78590, 38410 and 93718 in this paper). In the literature of MARL, a seed can be seen as a convention that governs the coordination among agents. Therefore, the post-training evaluation is aimed for evaluating the controlled agents' capability to interact with uncontrolled agents of unseen conventions. In contrast, during training we only focus on evaluating performance on the same seed as the one used for training.

To train SM-POAM on the StarCraft `3sv5z` task, run the following command: 
```
python src/main.py --env-config=sc2 --config=open/open_train_3sv5z --alg-config=sc2/poam_shapley with env_args.map_name=3s_vs_5z shapley_loss_coef=0.01 shaped_reward_coef=0.01 eps_clip=0.2 entropy_coef=0.05 truncated_TD_lambda=True m=7 value_loss_coef=0.5 gae_lambda=0.85 --local_results_path=3sv5z/open_train/poam_shapley_m7 --seed=[SEED]
```

To train SM-POAM on the StarCraft `5v6` task, run the following command: 
```
python src/main.py --env-config=sc2 --config=open/open_train_5v6 --alg-config=sc2/poam_shapley with env_args.map_name=5m_vs_6m shapley_loss_coef=0.001 shaped_reward_coef=0.01 eps_clip=0.2 entropy_coef=0.05 truncated_TD_lambda=True m=31 value_loss_coef=0.5 gae_lambda=0.85 --local_results_path=5v6/open_train/poam_shapley_m31 --seed=[SEED]
```

## Evaluating Models with Unseen Conventions and/or Uncontrolled Agents
We now look into how to evaluate trained models with unseen conventions (seeds) and/or uncontrolled agents. The function is implemented in `src/nk_evaluation.py`.

This script does **not** take command-line flags for the experiment setup. Edit the `__main__` block in `src/nk_evaluation.py`, then run:

```
python src/nk_evaluation.py
```

By default it calls `target_set_eval`, which evaluates each trained algorithm in `algs_to_eval` against each teammate type in `target_algs`. For every seed pair, it runs an **N-k** evaluation: team size is `num_agents`, and `k = 1, ..., N-1` is the number of uncontrolled teammates (the remaining `N-k` slots are filled by the trained agents). Each evaluation is launched through `src/run_eval.py` → `src/main.py` with `src/config/open/open_eval_default.yaml`.

**Before running, set these fields in `__main__`:**

1. **`base_path`**: directory that contains per-task result folders (the same root as `base_results_path` in `src/config/user_info.yaml`, e.g. `./naht_results`).
2. **Task**: uncomment one of `5v6`, `8v9`, `10v11`, `3sv5z`, or `mpe-pp`, and set `expt_dir`, `num_agents`, and `env_nickname` consistently.
3. **`algs_to_eval`**: relative paths (under `{base_path}/{expt_dir}/`) to the trained NAHT runs. These should match `--local_results_path` from training, without the task prefix. For example, after training with `--local_results_path=5v6/open_train/poam_shapley_m31`, use `"open_train/poam_shapley_m31"`.
4. **`target_algs`**: uncontrolled agent algorithm folders under `{base_path}/{expt_dir}/`, e.g. `["vdn", "qmix", "iql", "mappo", "ippo"]`. Checkpoints are loaded from `{base_path}/{expt_dir}/{alg}/models/`. If you downloaded uncontrolled agents into `./uncntrl_agents`, copy them so that layout exists (e.g. `naht_results/5v6/vdn/models/...`). Note that if you are aimed at testing performance against unseen uncontrolled agents, you should input the algorithm names that have not appeared during training.
5. **Seeds**:
   - `algs_to_eval_seeds`: trained-agent seeds. The paper uses `112358, 112359, 112360, 112361, 112362`.
   - `target_algs_seeds=["112358"]`: **in-distribution** evaluation (same convention as training).
   - `target_algs_seeds=["1285842", "78590", "38410", "93718"]`: **unseen-convention / OOD** evaluation.
6. **`dest_results_name`**: output folder name under `{base_path}/{expt_dir}/`. For example, you can use `"in_distr_eval"` for the in-distribution split and `"ood_generalization"` for unseen seeds.
7. Optional: set `DEBUG = True` to print the generated commands without running evaluations; set `USE_CONDOR = True` only if you are submitting jobs to HTCondor.

The expected layout is:

```
{base_path}/{expt_dir}/
  open_train/<your_run>/models/     # trained NAHT checkpoints
  vdn/models/                       # teammate checkpoints
  ...
  {dest_results_name}/
    <trained_alg>-vs-<target_alg>/  # Sacred eval logs written here
```

`expt_basenames=["baseline"]` must match the `label` used at training time (the default open-train configs use `label: baseline`). Already-finished evals are skipped when `skip_existing=True`.

## Aggregating and Plotting N-k Evaluation Results

After `src/nk_evaluation.py` finishes, scripts in the repo root and `src/` post-process the Sacred logs.

```
src/nk_evaluation.py
        ↓  Sacred logs
{task}/{dest_results_name}/{alg}-vs-{target}/sacred/.../metrics.json
        ├─→ calculate_mean_performance_by_n.py
        │         ↓
        │   all_mean_performance_by_n.json
        │         ↓
        │   visualize_metrics_by_n.py          one figure; pools all opponents per trained algorithm
        │   visualize_metrics_by_target.py     one figure per target / opponent algorithm
        │
        └─→ src/ood_figure_main.py             grouped bars for convention (unseen-seed) generalization
            src/ood_figure_type.py             grouped bars for type generalization
```

None of these scripts take experiment CLI flags. Edit the path/config block at the top (or `__main__`), then run `python <script>.py`.

### `calculate_mean_performance_by_n.py`
Aggregates N-k eval metrics by the `n-k` token in each Sacred run folder name. Set `base_dir` in `__main__` to the evaluation output directory, for example:

```python
base_dir = "./naht_results/5v6/ood_generalization"
```

Then run:

```
python calculate_mean_performance_by_n.py
```

The script walks `base_dir/<alg>-vs-<target>/sacred/`, reads each run's `1/metrics.json`, and writes means and 95% CIs to:

```
{base_dir}/all_mean_performance_by_n.json
```

Re-run it once per task and evaluation split (in-distribution, OOD, type generalization, etc.), each time with the matching `base_dir`.

### `visualize_metrics_by_target.py`

Uses the same JSON, but draws a **separate figure per target algorithm** (the name after `-vs-`, e.g. `ippo`, `vdn`). Configure it like `visualize_metrics_by_n.py`, then:

```
python visualize_metrics_by_target.py
```

Outputs are named `{FIGURE_NAME_PREFIX}_{target}_by_n.pdf`. Error bars are 95% CIs.

### `visualize_metrics_by_n.py`

Plots metric vs. number of controlled agents **N**, pooling a trained algorithm across all opponents. It requires `all_mean_performance_by_n.json`. Set at the top of the file:

- `SCENARIO_DIRS`: per-task result roots
- `TARGET_SUBDIR`: must match `dest_results_name` from `nk_evaluation.py` (e.g. `"ood_generalization"`)
- `EXP_NAMEMAP`: log name → legend name
- `OUTPUT_DIR` / `FIGURE_NAME`: where to save the PDF

```
python visualize_metrics_by_n.py
```

Error bars are 95% CIs.

The scripts below are an **alternative** plotting path: they read Sacred eval logs directly via `get_ood_gen_scores1` in `src/utils/vis_utils.py` (they do **not** use `all_mean_performance_by_n.json`). They draw grouped bar charts of overall OOD scores (aggregated over all `k`), with 95% CIs. Edit `os.chdir(...)` and `BASE_RES_PATH` at the top of each file to your clone, put `src` on `PYTHONPATH`, then run the script.

### `src/ood_figure_main.py`

Plots **unseen-convention (seed) OOD** generalization. For each task it loads:

- OOD scores from `{BASE_RES_PATH}/{task}/ood_generalization_baseline`
- in-distribution baselines from `{BASE_RES_PATH}/{task}/in_distr_eval_baseline` (drawn as red stars on the bars)

`target_algs` is the full teammate set (`vdn`, `qmix`, `iql`, `ippo`, `mappo`). Uncomment the desired `algs_to_eval` block and set `exp_namemap` to the algorithms you want in the legend. Then:

```
PYTHONPATH=src python src/ood_figure_main.py
```

The figure is saved under `savedir` / `savename` (currently `plots-naht/5trials-95ci/main-ood-baseline-mpe.pdf`). These folders must match `dest_results_name` from `nk_evaluation.py`.

### `src/ood_figure_type.py`

Plots **type generalization**: trained agents are evaluated against held-out teammate types (here `vdn` and `ippo`) from `{BASE_RES_PATH}/{task}/type_generalization_poam`. It does not overlay in-distribution baselines. Set `exp_namemap`, `target_algs`, and the per-task `algs_to_eval` dict, then:

```
PYTHONPATH=src python src/ood_figure_type.py
```

The figure is saved as `plots-naht/5trials-95ci/type-ood-poam.pdf` by default. Use this after running `nk_evaluation.py` with `dest_results_name` pointing at the type-generalization split.

## Verifying the Number of N-step Return Components
We additionally study whether setting the number of n-step return components, $m$, according to the number of non-empty coalitions is an effective choice for TTD($\lambda$). Using the SM-POAM training commands above, repeat each run over the five experimental seeds while changing `m` and assigning each setting a separate `--local_results_path`. The plotting script currently compares the following runs:

- MPE Predator-Prey: `m=7` (the coalition-based choice) against `m=3`, `m=14`, and `m=100`.
- SMAC `5v6`: `m=31` (the coalition-based choice) against `m=20` and `m=70`.
- SMAC `8v9`: `m=120` (the coalition-based choice) against `m=20`.

After the runs finish, update the paths in the `configs` variable of `main_m.py` if necessary and generate the comparison figure with:

```
python src/main_m.py
```

The script reads `test_return_mean` for MPE and `test_battle_won_mean` for SMAC from the TensorBoard event files in each run's `tb_logs/` directory. It aligns runs onto a common timestep grid, applies exponential moving-average smoothing, and plots the mean performance across seeds with 95% confidence-interval bands. It also prints performance summaries at five-million-timestep intervals. The resulting three-panel figure is saved as `plots-naht/main_m.pdf`.

## Evaluation Learning Curves during Training
`main_figure.py` plots learning curves directly from the TensorBoard event files under each configured run's `tb_logs/` directory. It compares POAM, IPPO-NAHT, SM-POAM, SM-IPPO, BM-POAM, and BM-IPPO across MPE Predator-Prey and the four SMAC tasks. Curves from different seeds are aligned to a common timestep grid, smoothed with an exponential moving average, and aggregated with 95% confidence-interval bands.

The evaluation criterion is controlled by `scalar_data_mode` near the top of the script. Enable the desired entry to generate a corresponding figure:

- `test`: `test_return_mean` for MPE and `test_battle_won_mean` for SMAC.
- `train`: `train_return_mean` for MPE and `train_battle_won_mean` for SMAC.
- `entropy`: policy entropy.
- `critic_loss`: critic loss.

The `test` mode is enabled by default. Uncomment another entry, or replace the list with the desired mode, to produce figures for a different criterion. Multiple enabled entries are processed in one execution and saved separately using their mode names.

After checking that the run directories in `configs` point to the intended experiments, run:

```
python src/main_figure.py
```

Figures are saved under `plots-naht/` as `main_<mode>.pdf`; for example, the default setting produces `plots-naht/main_test.pdf`.

Some notes about the algorithm running script arguments: 
- Change the `--env-config` to one of the supported environment configs under `src/config/envs/`.
- Change the `--config` to the config corresponding to the selected environment and task. Supported env/task combinations and corresponding hyperparameters *for the NAHT experiments* may be found under `src/config/open`.
- Change the `--alg-config` argument to the name of the appropriate algorithm config file, found under `config/algs/<env_name>`. The hyperparameters used for the paper are the values contained within these configs.  

Some notes about the task configs: 
- `src/config/open/open_algs_<task>.yaml`: 
    - Check that the checkpoint paths for each desired teammate type are correct (under `uncntrl_agents`). Paths should be relative to the `base_uncntrl_agents` specified in `src/config/user_info.yaml`
    - If running Shapley Machine and POAM, set `agent_loader` to `poam_train_agent_loader`. Else, set `agent_loader` to `rnn_train_agent_loader`
